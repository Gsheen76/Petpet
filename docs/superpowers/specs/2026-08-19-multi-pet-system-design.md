# Petpet 多宠物系统设计

**日期**：2026-08-19
**状态**：设计已确认，尚未实现

## 目标

将当前桌面宠物与家园宠物从两套不同形象，演进为可购买、可切换的多宠物系统。首期统一使用午餐肉；当前家园小狗作为第二只宠物冰淇淋显示在宠物商店中，正式动画资源后续补齐。

玩家可修改每只宠物的昵称。午餐肉和冰淇淋是默认初始名字，不是不可变的系统名称。

## 已确认范围

- 商店新增栏目名称：`宠物`。
- 新用户默认拥有并激活 `lunch_meat`，默认昵称为“午餐肉”。
- `ice_cream` 使用当前家园小狗作为资源来源，首期显示在宠物商店中但不默认拥有。
- `ice_cream` 原价为 `1000 Pet币`，按 `76 折`销售，实际购买价格为 `760 Pet币`；购买使用玩家共享 Pet币，购买成功后自动切换。
- 桌面和家园使用同一个 `active_pet_id`，切换后同步显示同一只宠物。
- 首期不增加复杂动作预览槽位；商店显示宠物主待机图、名字和拥有/购买/使用状态。
- 尚未制作的动作允许暂时使用静态待机图或简单方块占位资源；正式资源上传后直接替换。
- 运行时动作缺失时回退到当前宠物自己的静态待机图，不借用其他宠物的动作。

## 数据模型

保留单一 `pet_state.json` 作为迁移入口，增加玩家共享区与宠物独立区：

```json
{
  "active_pet_id": "lunch_meat",
  "owned_pet_ids": ["lunch_meat"],
  "level": 1,
  "xp": 0,
  "pet_coins": 0,
  "owned_home_decorations": [],
  "pets": {
    "lunch_meat": {
      "name": "午餐肉",
      "hunger": 100,
      "mood": 100,
      "energy": 100,
      "affection": 0,
      "affection_level": 1,
      "desktop_position": null,
      "home_position": null
    }
  }
}
```

### 玩家共享数据

`active_pet_id`、`owned_pet_ids`、等级、经验、Pet币、家具库存/位置、成就、强化、小游戏成绩和玩家账户进度共享。

### 宠物独立数据

每只宠物独立保存默认名/昵称、饱腹、心情、精力、睡眠状态、好感、宠物互动记录、桌面/家园位置、聊天记忆和用户画像。

切换宠物只更新 `active_pet_id`，不复制、重置或串写任何一只宠物的独立数据。

## 旧存档迁移

- 新存档创建 `lunch_meat` 并激活它。
- 旧存档当前名字、属性、好感、睡眠状态和位置迁移到午餐肉；已经改过的名字必须保留。
- 旧 `memory.json` 和 `memory-home.json` 合并到午餐肉记忆，后续宠物使用独立 memory profile。
- 等级、经验、Pet币、家具、成就、强化和购买记录原样保留。
- 迁移必须幂等，不能重复合并聊天、重复发放货币或覆盖昵称。

## 资源注册表

新增 `assets/runtime/pets/manifest.json`，为每只宠物声明稳定 ID、默认名、价格、预览图、桌面资源、家园资源和已有动作。

首期午餐肉复用已验证的桌面资源，家园也使用午餐肉的待机图；当前家园小狗资源归档为冰淇淋的后续资源来源。资源缺失不阻塞启动，渲染层按当前宠物的静态待机图回退。

宠物身份和套装保持独立：玩家拥有的套装是共享库存，装备状态按宠物保存；没有适配动画时回退当前宠物待机图。

## 商店与切换

宠物卡显示待机预览图、当前昵称、拥有/使用状态和购买价格。购买成功后自动切换；切换已拥有宠物时保存 `active_pet_id`，刷新桌面和家园并回到新宠物待机。改名只修改当前宠物。

宠物注册表必须同时保存 `original_price`、`discount` 和最终 `price`，避免 UI 或购买逻辑重复计算折扣。冰淇淋的值固定为 `1000`、`0.76`、`760`。

## 渲染同步

桌面和家园都通过当前宠物资源解析接口取得资源：

```text
active_pet_id -> pet registry -> pet profile -> scene animation lookup -> idle fallback
```

切换时清理旧动作并刷新两个场景；互动、睡觉、挖宝和玩耍状态机保持不变，只替换资源来源。

## 测试与验收

- 新存档默认拥有并激活午餐肉。
- 旧存档迁移到午餐肉且重复启动幂等。
- 等级、经验、Pet币、家具等共享数据切换前后不变。
- 两只宠物的属性、好感、昵称、位置和聊天记忆互不串写。
- 桌面和家园同步读取 `active_pet_id` 并刷新。
- 宠物商店正确显示午餐肉与冰淇淋。
- 缺失动作回退当前宠物待机图；占位资源不导致启动崩溃。
- 现有装扮、家园、小游戏、聊天、更新和存档兼容测试不回归。
