# Petpet 聊天模式选择设计

## 目标

将聊天入口简化为明确的两种模式：`免费聊天` 与 `自己配置 API`。模式不再根据是否保存 API Key 自动切换；用户选择自配模式时，在同一个配置弹窗内选择模型并填写 Key。

## 交互

- 聊天窗口底部仅保留一个聊天模式按钮、按需出现的上传图片按钮与清除记忆按钮。
- 点击模式按钮弹出两个选项：`免费聊天`、`自己配置 API`。
- 选择免费聊天后立即保存模式，使用项目方 OpenRouter 免费代理；已保存的个人 Key 保留但不启用。
- 选择自己配置 API 后打开配置弹窗。弹窗包含模型下拉框、密码式 Key 输入框，以及保存、取消和移除本机 Key操作。
- 当前个人模型只有 `GLM-4.6V-Flash`，数据结构仍允许以后增加模型。
- 若用户取消配置、没有可用 Key，则保持原模式；环境变量 `ZHIPU_API_KEY` 仍可作为个人 Key 来源。
- 上传图片按钮仅在自配模式且所选模型支持视觉输入时显示。

## 配置与兼容

- `config.json` 新增 `chat_mode`，合法值为 `default` 或 `personal`。
- 旧配置未包含 `chat_mode` 时：存在个人 Key则迁移为 `personal`，否则迁移为 `default`，保持旧用户行为。
- `model` 只保存个人模式使用的模型；免费模式固定显示 OpenRouter 免费路由，不占用个人模型选项。
- 移除本机 Key 不强制删除已选模型；若个人模式没有任何可用 Key，发送时给出配置提示而不偷偷切回免费模式。

## 请求边界

- Worker 最多接收 7 条消息。
- `system` 消息每条最多 4000 字符；`user` 与 `assistant` 每条最多 1200 字符。
- 整个请求继续限制为 16 KiB。客户端先按角色裁剪，再从最旧历史开始减少内容；仍超限时对系统提示按 UTF-8 字节预算继续裁剪，并保留其开头和结尾。
- 免费回复继续限制为最多 200 输出 token。

## 验证

- 配置测试覆盖显式模式、旧配置迁移、保留个人 Key、缺少 Key 时不自动切换。
- UI 测试覆盖单一模式按钮、选择免费模式、自配弹窗入口与图片按钮可见性。
- Worker 测试覆盖 4000/4001 字符系统消息边界、普通消息 1200/1201 字符边界及 UTF-8 总大小。
- 运行 focused tests、Worker 测试与完整 `pytest -q`。
