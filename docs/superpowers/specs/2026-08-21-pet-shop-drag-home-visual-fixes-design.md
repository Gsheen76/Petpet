# 宠物商店、拖拽与家园视觉修复设计

## 目标

修复三项已确认的界面与资源一致性问题：

1. 宠物商店卡片右边缘与套装、家居、强化页面对齐，保留现有信息并保持宠物介绍单行显示。
2. 桌面拖拽与其他渲染状态只使用当前宠物可用的套装和资源，冰淇淋不得显示午餐肉图像。
3. 家园待机与走路状态的可见宠物主体高度一致，切换状态时脚底位置不跳，阴影贴合当前帧的实际脚部区域。

## 方案

采用最小的共享逻辑修复，不新增宠物专属倍率配置。

### 宠物商店布局

宠物卡复用套装卡已经稳定的三段结构：左侧预览、中间信息、信息区内的标题行与底部操作行。状态徽章移动到标题行右侧，价格与操作按钮放在底部同一行，删除单独占用 180 像素的右侧操作栏。

宠物预览尺寸、名称、状态、单行介绍、售价和操作按钮全部保留。卡片允许随滚动区域宽度收缩，且不产生水平滚动或右侧裁切。

### 当前宠物与套装隔离

套装定义已有 `pet_id`。统一的已装备套装解析只在套装所属宠物与 `active_pet_id` 一致时返回该套装；不一致时视为当前宠物未装备套装，但不删除保存的数据。因此切换到冰淇淋后，桌面待机、拖拽和家园共享帧不会使用午餐肉套装；切回午餐肉后原套装仍可恢复。

### 家园主体尺寸与脚底锚点

非精灵表图像不再使用整张透明画布作为源矩形，而使用其 alpha 非透明边界。渲染高度继续沿用现有走路基准，裁剪后的可见主体将填满同一基准高度。所有状态仍以世界坐标中的脚底位置为底部锚点。

走路帧继续使用已有逐帧脚部接触数据。待机共享帧以裁剪后主体的水平中心、实际底部和保守脚宽生成阴影，从而避免透明边距导致的阴影偏移和主体缩小。

## 数据流

1. 商店切换宠物后，应用事务更新 `active_pet_id` 并刷新桌面与家园资源。
2. 桌面渲染查询当前有效套装；跨宠物套装返回空，随后使用当前宠物的动画或静态待机资源。
3. 家园读取桌面共享帧或家园专用帧，计算非透明源边界，按统一高度和脚底锚点绘制，并据接触数据绘制阴影。

## 错误与回退

- 图像为空或没有可见 alpha 时，保留完整源矩形回退，避免渲染异常。
- 当前宠物没有专属动作时，继续回退到该宠物自己的待机图，不跨宠物查找。
- 不修改存档结构，不迁移或清除已装备套装数据。

## 测试与验收

- 宠物页卡片宽度不超过标签栏/滚动视口的可用宽度，且名称、介绍、价格、状态和按钮均存在。
- 当前宠物为冰淇淋且存档仍记录午餐肉套装时，有效套装、套装动画和拖拽预览均为空；切回午餐肉后恢复。
- 透明边距图像返回实际 alpha 边界；全透明或空图像安全回退。
- 家园待机与正面走路的渲染高度一致，底边一致；阴影中心和底部跟随待机脚部接触点。
- 运行相关测试与完整测试套件，随后从 `main` 重启小狗供人工验证。

## 非目标

- 不新增宠物资源编辑器或每宠物手工缩放配置。
- 不重做商店整体视觉风格。
- 不改变宠物资源目录和 16 帧动画内容。
