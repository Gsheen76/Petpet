# 小狗聊天台词与游戏知识库设计

## 目标

让小狗的聊天消息只呈现自然台词，不显示小狗图标或括号动作描述；同时提供随 Petpet 版本维护的本地游戏知识库，让玩家可在聊天中询问已发布的游戏玩法与功能。

## 聊天台词呈现

- 聊天记录中的助手气泡直接显示模型文本，不再由 `ChatWindow` 自动前置 `🐶`。
- 聊天窗口标题只显示小狗名字；本轮不制作头像，也不增加头像槽位。用户以后提供头像后，可在该位置单独接入。
- 人设提示词追加台词规则：只写自然、口语化的对话；不写舞台动作、旁白或圆括号/半角括号内容。
- 显示层使用确定性兜底清理：删除成对的 `（…）` 和 `(...)` 片段，并删除残留的同类括号字符，再呈现文本。功能名避免使用括号表达，以免被误删。
- 该清理同时适用于在线回复与离线回复，历史中已有内容保持原样，避免篡改已保存的用户记录。

## 本地游戏知识库

### 文件与边界

- 新建 `assets/knowledge/game_knowledge.json`，与代码一起发布，离线可用。
- 文件包含 `version`、`entries` 和每条知识的 `id`、`title`、`keywords`、`content`。
- `version` 必须与 `version.py` 的 `VERSION` 一致；每次功能发布前把面向玩家的新增玩法写入资料并更新该值。
- 知识只记录已实现、面向玩家的内容，不读取 Obsidian 开发笔记，不包含 API Key、内部路径、未发布计划或测试细节。

### 首批内容

- 基本互动：抚摸、喂食、玩耍、睡觉、好感与属性。
- 快捷菜单：聊天、小屋、商店、互动、更多的入口与用途。
- 小屋：左键移动、右键互动、家具装修与地毯睡眠。
- 成长与经济：记录、成就、Pet 币、商店、强化与装扮。
- 小游戏：金币雨与幸运爪爪。
- 聊天：模型切换、图片聊天、图片隐私和离线回退。

### 注入与回答

- 每次用户发送消息时，以关键词匹配知识条目，最多选取三个最相关条目并附在系统提示词的“游戏资料”部分。
- 无匹配时不注入任何游戏资料，普通陪伴聊天的上下文与长度不受影响。
- 询问游戏玩法时，小狗优先根据资料给出简短、准确、面向玩家的回答；不知道或资料没有覆盖时诚实说明，并引导玩家查看相应界面。
- 资料不会写入 `memory.json`，也不会替代玩家个人对话记忆。

## 维护流程

每次新增或改变玩家可见功能时：

1. 更新 `assets/knowledge/game_knowledge.json` 的相关条目与 `version`。
2. 在测试中确认资料版本与 `VERSION` 一致、条目结构有效、代表性问题能匹配预期知识。
3. 更新 README 与 Obsidian 的聊天系统记录，说明新增的玩家知识范围。

## 验收

- 助手消息气泡没有自动 `🐶` 前缀。
- 输入含中英文括号动作的助手文本后，界面只显示括号外台词。
- `game_knowledge.json` 版本与应用版本一致，所有条目具有非空标题、关键词和内容。
- “怎么装修”“怎么增加好感”“小屋怎么移动”“怎么上传图片”等问题各自注入正确资料；普通闲聊不注入资料。
- focused tests、完整 `pytest -q`、`py_compile` 和 `git diff --check` 通过。

## 实施结果

- 新增 `assets/knowledge/game_knowledge.json` 与 `game_knowledge.py`，以 `version.py` 的 `VERSION` 校验随版本打包的玩家玩法资料。
- 聊天提示词仅在关键词命中时追加最多三条本地资料；资料不会写入聊天记忆，也不会读取 Obsidian 或网络内容。
- 助手气泡、保存内容与桌宠说话气泡都会清理括号动作说明；标题与助手气泡不再自动添加狗狗图标。
