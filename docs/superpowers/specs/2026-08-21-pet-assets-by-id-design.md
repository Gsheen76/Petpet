# 宠物 ID 资源目录迁移设计

**日期**：2026-08-21
**状态**：待评审

## 目标

将运行时宠物资源从“桌面 / 家园”优先的共享目录，迁移为“宠物 ID”优先的目录。新增宠物时，只需在自己的目录补充桌面、家园和服装资源，不会与其他宠物混放。

## 目录结构

```text
assets/runtime/pets/
  lunch_meat/
    desktop/
      poses/
      animations/
      outfits/
  ice_cream/
    desktop/
      poses/
      animations/idle/000.png … 015.png
    home/
      poses/
```

- 现有 `pets/desktop/` 全部迁入 `pets/lunch_meat/desktop/`。
- 现有 `pets/home/` 全部迁入 `pets/ice_cream/home/`。
- 家具、场景、通用音效、通用道具和 `assets/source/` 保持共享目录，不进入宠物 ID 目录。
- 不保留旧运行时目录副本，避免两个来源逐渐漂移。

## 冰淇淋待机帧

- 输入为用户提供的 4×4 图集，共 16 格；按从左到右、从上到下切分，完整写为 `000.png` 到 `015.png`，不跳帧、不重复帧。
- 每格先移除统一橙色背景并保留狗的边缘抗锯齿；输出为透明 PNG，保持图中角色完整，不裁掉耳朵、尾巴或脚。
- `ice_cream` 的桌面动画 manifest 定义 `idle` 为 16 帧循环；首帧同时作为 `desktop/poses/idle.png`，为静态预览和无动画回退提供资源。

## 当前宠物同步

- 桌面宠物和家园宠物都以同一个活动宠物 ID 解析资源；切换宠物后，两个场景都显示该宠物，不能因为进入家园而换成另一只狗。
- 午餐肉目前没有家园专用走路/睡眠图时，家园各动作回退到午餐肉自己的桌面待机图；不得回退到冰淇淋或任何其他宠物。
- 冰淇淋的桌面待机使用本轮导入的 16 帧循环；其家园动作继续使用冰淇淋目录中的家园图。

## 加载与兼容

- `assets/runtime/pets/manifest.json` 的每个宠物只指向自己的相对路径，例如 `pets/ice_cream/desktop/...`。
- 运行时依据活动宠物 ID 从 manifest 解析桌面、家园姿势和动画 manifest；桌面窗口与家园窗口都不能再假定单一共享 `pets/desktop` 或 `pets/home`。
- 删除对固定家园宠物路径的运行时依赖；家园窗口通过活动宠物 ID 与 `pet_asset_path()` 取得动作，并在当前宠物目录内回退。
- 不改宠物 ID、价格、存档、购买资格、动画动作名、家具比例或共享资源路径。

## 验证

- 打包资源测试确认新目录被包含，旧 `pets/desktop` 与 `pets/home` 运行时目录不存在。
