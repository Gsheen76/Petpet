# Petpet v1.4.0 发布设计

## 目标

将当前 `codex/home-scene-system` worktree 中已经验证的家园系统、家具装修、快捷菜单和小屋宠物行为整理为 Petpet `v1.4.0`，同时更新 README、发布说明和版本元数据，并向 GitHub Release 一次性提供完整的 Windows 与 macOS 双架构资产。

## 发布边界

- 唯一版本来源 `version.py` 更新为 `1.4.0`。
- README 当前版本与更新亮点更新为 `v1.4.0`。
- README 操作表反映实际入口：主菜单直接进入“小屋”，不再描述为“更多 → 家”。
- 新增 `docs/RELEASE_NOTES_v1.4.0.md`，说明快捷菜单、家场景、家具装修、2.5D 小狗移动、寻路反馈、待机、对话和睡眠动画。
- 保留当前所有未提交功能改动，不回退其他文件。
- 不加入与本轮家园功能无关的新功能或重构。

## 资产与公开策略

Release 标签为 `v1.4.0`，标题为 `Petpet v1.4.0`，包含四个资产：

1. `Petpet.exe`
2. `Petpet-v1.4.0-windows.zip`
3. `Petpet-v1.4.0-macOS-arm64.zip`
4. `Petpet-v1.4.0-macOS-intel.zip`

Windows 资产从当前 worktree 的已验证提交本地构建。macOS 资产由 GitHub Actions 的 `Build macOS app` 工作流在同一提交上构建。先创建草稿 Release 并上传全部资产；四个文件名称、大小和下载状态均验证通过后才公开，避免产生只有部分平台包的正式版本。

## Git 流程

当前 worktree 已位于命名分支 `codex/home-scene-system`，且分支起点包含本地主分支尚未推送的提交。发布实施会：

1. 在当前分支完成文档、版本和测试改动。
2. 创建一个包含当前家园功能与 `v1.4.0` 元数据的发布提交。
3. 在不切换工作区的情况下，把发布提交快进推送到 `origin/main`。
4. 创建并推送带注释标签 `v1.4.0`。
5. 以该标签对应提交构建和上传资产。

任何非快进推送、远端冲突、工作流失败、资产缺失或测试失败都会停止公开步骤；不使用强制推送。

## README 内容

README 的 `v1.4.0 更新亮点` 聚焦以下用户可见变化：

- 快捷菜单调整为“聊天、小屋、商店、互动、更多”，互动页提供抚摸、喂食、玩耍和睡觉。
- 新增固定右下区域的家场景和独立家具装修侧栏。
- 家具支持购买、放置、拖动、缩放、旋转、收纳与状态保存。
- 小屋中支持左键指定目的地、脚印路线和终点反馈。
- 小屋小狗支持四向移动、正坐待机、同风格对话和走到地毯睡觉。
- 睡眠使用 8 帧、3 FPS 的独立动画并提供缺图回退。

项目结构补充 `home_pet.py`、`home_scene.py`、`scene_system.py` 和 `assets/scenes/home/`，发布说明列表补充 `RELEASE_NOTES_v1.4.0.md`。

## 测试与发布闸门

版本变更先通过 `tests/test_release_metadata.py` 的失败测试确认 RED，再修改 `version.py`、README 和发布说明使其 GREEN。正式构建前运行：

- `python -m pytest -q`
- `python -m py_compile pet.py home_pet.py home_scene.py scene_system.py progression.py progression_ui.py updater.py`
- `git diff --check`

Windows 构建后验证：

- `dist/Petpet.exe` 存在且可隐藏启动。
- `Petpet-v1.4.0-windows.zip` 仅包含正式可执行文件和必要说明。
- EXE 与 ZIP 均计算 SHA-256。

macOS Actions 完成后验证两个 ZIP 的文件名、非零大小和工作流结论。Release 公开后通过 GitHub API 再次核对标签、草稿状态、四项资产、大小和下载 URL。
