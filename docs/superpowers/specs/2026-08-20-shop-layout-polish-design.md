# 商店信息与双列布局设计

**日期**：2026-08-20
**状态**：已实现，未发布

## 目标

让商店的宠物、套装、家具和强化页面更容易浏览，同时保持现有暖色卡片视觉、购买行为、状态信息和素材展示比例。

## 范围

### 宠物页

- 每次新建 `ShopWindow` 时，若状态含多宠物数据，默认页固定为 `pets`，不读取或保存上次关闭时的页面。
- 宠物名称下增加一行可换行的简短介绍，沿用现有 `muted` 文字样式。介绍定义放在运行时宠物注册表中：午餐肉为“元气满满的陪伴小狗，喜欢在桌面上撒娇。”；冰淇淋为“安静温柔的家园小狗，期待和你一起生活。”。
- 宠物卡始终显示售价：免费宠物显示“售价：0 Pet币”，付费宠物显示当前应付 Pet 币；已拥有状态只留在右侧状态徽章和操作按钮，不再替换价格文字为“已拥有”。
- 仍保留“使用中”“切换宠物”“免费领取”和购买按钮的现有语义。

### 免费物品排序

- 宠物、套装、装饰和家具页面都按定义中的原始 `price == 0` 先显示免费赠送物品；同一价格组内保持现有注册表/定义顺序。
- 强化不是赠送商品，不改变其固定的强化定义顺序。
- 排序只改变 UI 生成卡片的顺序，不改变价格、首购折扣、拥有状态、购买校验或存档中的列表顺序。

### 家具双列

- 家具页面改为两列等宽 `QGridLayout`，每项卡片都继续显示：预览图、名称、拥有/家居状态、完整介绍、价格文字和领取/购买状态按钮。
- 单张家具卡改为垂直布局；预览区保持 `170 × 112` 逻辑尺寸，并继续使用 `Qt.KeepAspectRatio`，因此不会拉伸、裁切或缩小图片的展示比例。
- 卡片最小高度按内容留足，避免介绍、价格或按钮被压缩；窗口与滚动区域继续负责纵向浏览。

### 强化当前效果

- 每张强化卡在现有简介后增加一行“当前加成：…”。
- 文字直接调用 `progression.upgrade_description(state, upgrade_id)`，使用与实际生效强化相同的计算路径；例如等级为 0 时展示基础效果，购买后刷新页面立即展示新数值。
- 不改强化的等级上限、价格、结算和效果计算。

## 实现边界

- 修改 `assets/runtime/pets/manifest.json`，仅为两只已注册宠物补 `description` 文本。
- 修改 `petpet/progression/ui.py` 的 `ShopWindow`：默认页、宠物描述/价格、四类商品的稳定免费优先排序、家具网格与强化当前效果标签。
- 在 `tests/test_progression_ui_boundary.py` 增加 Qt 结构回归测试：默认宠物页、宠物描述与持久售价、免费优先顺序、家具两列/预览比例/信息完整性、强化当前数值。
- 不增加依赖、不更改 `petpet/progression/core.py` 的购买或强化规则、不修改玩家存档结构。

## 验收

1. 打开商店默认显示“🐾 宠物”页；切换页面后关闭再打开，仍显示宠物页。
2. 已拥有宠物卡显示其售价和一行简介，不再在价格区域显示“已拥有”。
3. 宠物、套装、装饰、家具中原始价格为 0 的条目位于各自页面最前，其他相对顺序不变。
4. 家具页每行两个卡片；每个卡片的介绍、价格、状态、按钮和 `170 × 112` 等比预览仍存在。
5. 强化页每张卡显示当前效果，购买后刷新显示更新后的值。
