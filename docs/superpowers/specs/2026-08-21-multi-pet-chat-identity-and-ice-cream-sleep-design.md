# 多宠物聊天身份与冰淇淋睡眠一致性设计

## 背景

当前聊天窗口的助手头像固定读取午餐肉的桌面 `idle.png`，切换到冰淇淋后仍显示午餐肉。聊天提示词也只有一套通用 Sheen 人格，构造提示词时没有使用稳定的宠物 ID，因此宠物改名后无法可靠区分性格。

聊天回复清理只合并横向空格，没有处理模型输出中的连续换行。`QLabel` 会原样显示 `\n\n`，所以截图中的两个段落之间出现一整行空白。

冰淇淋的桌面动画清单目前只注册待机序列。进入睡眠后，桌面播放器找不到冰淇淋睡眠帧，会回退到待机素材；而家园已有完整的 8 帧睡眠图。

## 已确认需求

- 助手头像随当前宠物变化，使用该宠物对应的桌面待机图。
- 连续空行压成一个正常换行，不删除单次换行，不改变玩家发送的文本。
- 午餐肉具有活泼开朗的独立人格；冰淇淋具有温柔可爱的独立人格。
- 人格按稳定 `pet_id` 选择，宠物改名后不得串人格。
- 聊天窗口左上角在宠物已改名时显示 `昵称（真实名）`；未改名或昵称等于真实名时只显示真实名。
- 输入框、清除记忆等日常文案继续只使用昵称。
- 冰淇淋桌面睡眠直接复用家园同一张 8 帧素材，播放速度同为 `3 FPS`。
- 冰淇淋桌面睡眠保持底部锚定，显示约 `118×57px`，与家园约 `118×58px` 一致。
- 午餐肉现有桌面睡眠动画不变。
- 完成后更新 Obsidian 开发记录并重启源码小狗。

## 方案比较

### 方案 A：宠物注册表驱动（采用）

宠物注册表继续作为稳定身份来源：真实名和人格提示由 `pet_id` 对应的定义提供；头像通过现有 `pet_asset_path()` 读取当前宠物待机图；聊天 API 将 `pet_id` 显式传到提示词构造入口。冰淇淋桌面动画清单声明家园睡眠 spritesheet，由现有动画加载器按元数据切帧。

优点是改名只改变昵称，不改变头像、人格或资源归属；新增宠物时也只需补注册信息和素材声明。

### 方案 B：在各调用点按宠物 ID 分支

在聊天 UI、提示词和动画加载处分别写 `if lunch_meat / ice_cream`。初始代码较短，但身份规则分散，后续容易再次出现头像、人格和动画不一致，不采用。

### 方案 C：每只宠物建立独立聊天配置和桌面睡眠副本

隔离最彻底，但会复制提示词结构和睡眠资源，增加同步成本；当前只有两只宠物，不值得引入，不采用。

## 详细设计

### 1. 注册表中的真实身份与人格

在 `assets/runtime/pets/manifest.json` 的每只宠物定义中增加 `chat_personality`：

- 午餐肉：活泼开朗、反应明快、喜欢表达开心和好奇；可以偶尔用“汪”、摇尾巴等小狗口吻，但不连续吵闹。
- 冰淇淋：温柔可爱、语气轻柔、擅长安慰与陪伴；用词柔软亲近，但不过度撒娇。

`default_name` 继续作为不可变的真实名。玩家保存的 `pet_name` 是昵称。人格、头像和动画均由稳定 `pet_id` 决定，昵称仅用于标题、自称和日常 UI 文案。

### 2. 提示词数据流

聊天窗口调用 `chat_stream(..., pet_id=self.pet_id, pet_name=self._pet_name())`。免费代理和自定义 Key 两条路径都把 `pet_id` 传给统一的 `_build_messages()`。

`_build_messages()` 用 `pet_definition(pet_id)` 读取 `chat_personality`，再把人格文本作为显式参数交给纯函数 `petpet.chat.service.build_messages()`。服务层不直接读取 UI 状态或全局注册表，继续只负责把基础陪伴规则、当前宠物人格、昵称、记忆、情绪提示和游戏资料组合成 system message。

共同规则继续适用于两只宠物：

- 保持小狗身份，不承认自己是 AI。
- 回答为口语化中文，控制在 1–3 句。
- 不写括号动作或舞台提示。
- 先共情再建议，不编造记忆。
- 游戏问题只使用已提供的游戏资料。

### 3. 聊天头像与标题

助手头像不再使用全局 `POSES_DIR`，而是调用：

```python
pet_asset_path(self.pet_id, "desktop", "idle")
```

继续复用当前圆形裁剪、暖色底和描边。切换宠物调用 `set_pet_id()` 后，现有 `_set_log_messages()` 会重建消息行，因此历史中的助手头像也会立即换成当前宠物的待机头像。玩家头像选择、恢复和右侧位置均保持不变。

标题由昵称和 `pet_definition(self.pet_id)["default_name"]` 生成：

```text
nickname == real_name  -> 冰淇淋
nickname != real_name  -> 奶油（冰淇淋）
```

输入框占位符、清除记忆提示和“正在思考”仍只显示昵称。

### 4. 回复空行清理

扩展现有 `clean_assistant_reply()`，在移除括号动作和合并横向空格后：

1. 统一 `\r\n` 和 `\r` 为 `\n`。
2. 去除每行行首、行尾的多余空格。
3. 把两个及以上连续换行压成一个 `\n`。
4. 对最终结果执行 `strip()`。

该函数已经用于历史消息渲染、流式中的临时气泡、最终保存内容和桌面说话气泡，因此在共同入口修复即可覆盖全部助手回复。玩家消息不经过此清理函数。

### 5. 冰淇淋桌面睡眠

冰淇淋桌面动画清单增加 `sleep` 声明，直接引用：

```text
assets/runtime/pets/ice_cream/home/poses/home-pet-sleep.png
```

声明包含：

- `frame_size: 640`
- `frame_count: 8`
- `columns: 3`
- `content_rect: [24, 176, 592, 288]`
- `fps: 3`
- `loop: true`
- `fallback: sleep`
- `scale: 0.62`
- `anchor_bottom: true`

桌面动画加载器在普通帧目录不存在、但声明了 `spritesheet` 时，从同一张图片按网格位置和共享内容矩形切出 8 张 `QPixmap`，再走现有的最大尺寸、颜色调整、帧缓存和播放逻辑。不创建第二套 PNG 文件。

以裁剪后的 `592×288` 比例放入 `190px` 桌面宽度并乘以 `0.62`，目标约为 `118×57px`；底部锚定使睡眠脚底线与桌面现有位置规则一致。家园仍直接读取原 spritesheet，二者视觉来源完全相同。

### 6. 失败与回退

- 注册表缺少人格时使用现有通用温暖陪伴人格，聊天不能因此失败。
- 当前宠物待机图无法读取时保留现有默认圆形小狗占位图。
- spritesheet 路径无效、尺寸不足或元数据非法时不产生部分帧，继续使用该动作既有静态回退。
- 不改变聊天网络路由、额度、模型参数、玩家头像或午餐肉动画。

## 测试设计

### 提示词与身份

- 用同一昵称分别构造午餐肉和冰淇淋消息，断言 system message 包含各自人格特征且互不混入。
- 将冰淇淋昵称改为“奶油”，断言仍选择冰淇淋人格，自称使用“奶油”。
- 免费和自定义聊天路径都传递稳定 `pet_id`。

### 文本清理

- 输入包含 Windows/Unix 换行、连续空行、行两侧空格和括号动作，断言只保留单换行和可见对白。
- 用户消息含连续换行时保持原文，不套用助手清理。
- 完成事件保存到历史并传给桌面说话气泡的文本均无空白行。

### UI

- 午餐肉与冰淇淋的助手头像来源分别指向各自桌面待机图。
- 切换 `pet_id` 后重绘历史，头像来源同步变化。
- 昵称“奶油”显示 `奶油（冰淇淋）`；昵称等于“冰淇淋”时只显示 `冰淇淋`。

### 桌面睡眠

- 用真实冰淇淋家园 spritesheet 加载桌面睡眠，断言得到 8 帧。
- 首帧和末帧的像素内容与家园对应源区域一致。
- 断言 `fps == 3`、`scale == 0.62`、`anchor_bottom == true`。
- 断言午餐肉仍加载原 12 帧睡眠动画和原参数。

### 回归与交付

- 运行聊天服务、聊天 UI、宠物注册、桌面动画和睡眠焦点测试。
- 运行完整 `python -m pytest -q`、Python 编译和 `git diff --check`。
- 使用 Obsidian CLI 写入并读回开发记录。
- 重启 `D:\Agent_project\Petpet\pet.py`，人工检查两只宠物头像、人格、标题、空行和冰淇淋桌面睡眠。
