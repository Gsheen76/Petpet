# 参数调试器 UI 与运行时反馈设计

## 背景

源码版参数调试器已经能够调用 `PetWindow.set_debug_parameter()`，但当前窗口尺寸和字体在关闭系统 DPI 缩放后偏小；同时只有一个全局状态文案，用户无法确认某一项已经写入哪个运行时目标。部分参数本来就要等下一次自动行为、互动或小游戏回合才体现，因此容易被误判为没有生效。

## 目标

- 在常见 1080p 和高分辨率桌面上提供可读、可点击的调试面板。
- 保持屏幕较小时自动限制窗口尺寸，不遮挡或溢出屏幕。
- 每次调节都即时写入当前 `PetWindow` 或对应的共享运行时配置。
- 让用户看到当前生效值与生效时机，不改变正式版设置和存档语义。
- 用真实 `PetWindow` 的回归测试验证关键参数确实改变运行时行为输入。

## 方案

### UI 布局

`ParameterTunerWindow` 的默认尺寸调整为约 `1080 x 920`，通过 `show_near_pet()` 按当前屏幕可用区域收缩。沿用设置页的独立像素字体策略，标题、分组标题、参数标签、辅助说明、数值框和按钮整体放大；滚动区保留，避免小屏内容被裁切。

参数行继续使用标签、说明、数值框、单项恢复按钮和滑块，但扩大间距与点击区域。每行增加一条轻量反馈文本，显示当前值和生效时机（例如“立即生效”“下一次自动行为生效”）。

### 运行时应用

保留 `PetWindow.set_debug_parameter()` 作为唯一应用入口。调试器控件通过一个统一的 `_apply_value()` 辅助方法同步滑块与数值框、调用应用入口、读取规范化后的当前值，并刷新行级反馈和顶部状态。这样可以避免控件显示值与实际被 clamp 后的运行时值不一致。

参数的运行时目标不改变：窗口/绘制尺寸和物理值写入 `PetWindow`，衰减写入当前 `settings`，自动行为写入 `PetWindow` 属性，好感/挖宝写入 `progression` 模块，动画和小游戏写入各自运行时规格。需要延迟体现的项目明确标记生效时机。

### 保存与恢复

“保存调试参数”继续只写 `debug_parameters.json`；“恢复默认”先应用默认值到当前进程，再由用户决定是否保存。复制功能继续导出规范化后的当前快照。所有操作保留现有成功/失败状态文案。

## 测试

- 扩展参数调试器 UI 测试，验证放大后的尺寸、关键控件存在、行级反馈更新以及滑块/数值框同步。
- 新增真实 `PetWindow` 运行时测试，覆盖窗口尺寸、绘制高度、物理参数、动画 FPS、衰减、自动作息、好感冷却、进食时长和小游戏参数。
- 运行完整 pytest 套件，确保现有桌宠、成长、聊天、打包和小游戏测试不回归。

## 非目标

- 不把调试参数暴露到打包版菜单。
- 不改变正式版设置窗口、用户存档格式或默认游戏平衡。
- 不在本次工作中增加新的调试参数类别。
