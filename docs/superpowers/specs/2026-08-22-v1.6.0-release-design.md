# Petpet v1.6.0 发布设计

## 目标

将当前 `main` 中自 `v1.5.2` 以来的全部已验证改动作为 `v1.6.0` 正式发布。Git 标签固定为 `v1.6.0`，GitHub Release 标题固定为 `Pet陪它 v1.6.0`，发布目标必须与远端 `main` 指向同一提交。

## 发布内容

`v1.6.0` 面向玩家归纳为五组变化：

1. 多宠物系统：新增冰淇淋，宠物可购买、切换，并按宠物保存昵称、属性、位置和聊天记忆；桌面与家园始终显示同一只当前宠物。
2. 独立资源与动画：资源按宠物 ID 组织；冰淇淋拥有 16 帧桌面待机动画，并在桌面与家园复用同一套 8 帧睡眠动画。
3. 商店与强化：宠物、套装、家具和强化页面统一卡片、折扣价格与免费赠送展示；家具保持双列和完整信息；互动恢复与消耗随强化等级变化，满级消耗归零。
4. 聊天身份：聊天头像、标题和性格随当前宠物切换；午餐肉活泼开朗，冰淇淋温柔可爱；清理助手回复中的多余空行和横向空格。
5. 稳定性与一致性：修复快速右键双击引发的菜单闪退，消除家园待机微小横移，统一桌面拖拽、家园待机、睡眠尺寸和脚底阴影。

## 版本元数据

- `version.py` 的 `VERSION` 改为 `1.6.0`。
- `assets/runtime/knowledge/game_knowledge.json` 的 `version` 同步为 `1.6.0`。
- `README.md` 当前版本、最新亮点、下载资产和一键发布命令全部指向 `v1.6.0`；保留 `v1.5.2` 历史亮点。
- 新建 `docs/RELEASE_NOTES_v1.6.0.md`，作为 GitHub Release 正文。
- `tests/test_release_metadata.py` 的公开版本和资产契约改为 `1.6.0`。

## 发布资产契约

公开 Release 必须是非草稿、非预发布，并至少包含以下四项非空资产：

1. `Petpet.exe`
2. `Petpet-v1.6.0-windows.zip`
3. `Petpet-v1.6.0-macOS-arm64.zip`
4. `Petpet-v1.6.0-macOS-intel.zip`

同时上传 `Petpet-v1.6.0-SHA256SUMS.txt` 作为 Windows 资产校验记录。macOS 继续使用未签名、未公证说明。

## 执行架构

发布工作在从当前 `main` 创建的干净隔离工作树中完成，以避开主工作区既有未跟踪文件。元数据提交通过测试后运行现有 `scripts/release.ps1 -Version 1.6.0`：脚本负责完整测试、Python 编译、Windows 构建与冒烟测试、原子推送远端 `main` 和带注释标签、创建草稿 Release、触发 macOS 双架构 Actions、校验所有资产，再公开 Release。

若系统没有 `gh`，下载官方 GitHub CLI 的便携版到已忽略的 `.tools/gh`，不新增项目依赖，不提交工具二进制。发布过程不得强制推送、覆盖已有标签或覆盖内容不同的远端资产。

## 失败与恢复

- 版本、说明、工作树或测试不符合要求时，在任何远端变更前停止。
- 若远端已存在指向不同提交的 `v1.6.0` 标签或 Release，停止并报告冲突。
- Windows 构建、冒烟测试或 macOS Actions 失败时保留草稿，不公开不完整 Release；修复后重复运行同一脚本。
- 只有四项必需资产均为 `uploaded`、大小大于零，并且远端 `main`、标签和发布提交完全一致时才公开。

## 验证与记录

发布提交前运行公开版本契约测试和完整测试。脚本完成后再次通过 GitHub API/CLI验证 Release 元数据、资产名称/大小、下载 URL、远端引用和本地 SHA256。最终将版本说明、提交、标签、Release URL、资产和验证结果写入 Obsidian 的 `项目/Petpet/发布系统`，并更新 Petpet 总档案中的当前公开版本。
