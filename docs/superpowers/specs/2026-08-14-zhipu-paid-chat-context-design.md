# 智谱付费聊天模型与充分上下文设计

日期：2026-08-14

## 目标

Petpet 的中国大陆免费聊天入口改用低成本付费模型 `glm-4.7-flashx`，避免免费模型日额度耗尽后整个聊天功能不可用。同时让模型获得适量且充分的输入，包括稳定的小狗人设、准确的游戏知识、长期用户记忆和近期对话上下文。

## 模型与成本边界

- 阿里云函数默认模型改为 `glm-4.7-flashx`。
- `ZHIPU_MODEL` 环境变量继续具有最高优先级，便于线上无代码切换。
- 保持流式输出，关闭思考模式。
- 单次最大输出保持 200 Tokens。Petpet 仍要求回复 1–3 句，避免等待和成本膨胀。
- 阿里云本地 20 次/北京时间日额度和 Cloudflare 独立额度逻辑不变。
- Cloudflare/OpenRouter 继续作为连接级故障兜底，不承担正常主流量。

## 输入上下文

公开代理契约统一调整为：

- 请求体最大 32768 字节；
- 系统消息最大 8000 字符；
- 普通单条消息最大 1600 字符；
- 最多 12 条消息；
- 实际发送最近 10 条历史消息，再附加当前用户消息。

系统提示词只包含以下稳定内容：

1. 小狗身份、性格、说话风格和安全限制；
2. 主人的长期资料摘要；
3. 当前时间和情绪提示；
4. 与本次问题相关的游戏知识。

近期对话只以标准 `user` / `assistant` 消息发送，不再同时嵌入系统提示词，避免重复消耗输入。超过限制时优先删除最旧的对话；人设、长期记忆、相关知识和当前问题必须保留。

## 游戏知识库

- 新增“Petpet 游戏概览”条目，准确说明桌面陪伴、小屋、互动、状态成长、好感、Pet币、商店、装修、小游戏、宝藏、设置和聊天。
- 审核并更新现有条目，使其与当前 v1.4.1 代码行为一致，不描述未发布功能。
- 知识库采用按需检索：只有玩家问题命中游戏名称、玩法或功能关键词时才执行检索并注入知识。
- 普通问候、情绪陪伴和日常闲聊不携带游戏知识，系统提示词中也不预置完整知识库。
- 命中游戏问题后，相关知识检索从最多 3 条提高到 5 条；具体问题只注入最相关条目。
- “介绍游戏”“怎么玩”“Petpet 有什么功能”等宽泛问题必须命中游戏概览。
- 模型只能依据注入的已发布资料回答玩法；资料未覆盖时应明确表示不知道，不能猜测。

## 错误诊断

智谱返回非 200 时，阿里云日志额外记录安全的数值业务错误码，例如 1302、1304、1305 或 1113。不得记录 API Key、用户消息、系统提示词或智谱完整错误文本。

## 验证

- Python 测试覆盖消息数量、上下文裁剪优先级、去重、知识命中和模型配置。
- Python 测试同时确认日常聊天不注入任何游戏资料，游戏相关问题才按需注入。
- 阿里云与 Cloudflare 测试覆盖统一请求契约。
- 阿里云测试确认默认模型为 `glm-4.7-flashx`、输出上限 200、思考关闭，以及安全错误码日志。
- 运行聊天 focused tests、代理测试和完整 `pytest -q`。
- 生成新的阿里云根目录部署 ZIP，并记录 SHA-256；部署动作仍由用户在阿里云控制台完成。

## 不在范围内

- 不修改个人 API 图文聊天的 `GLM-4.6V-Flash`。
- 不提高单次输出长度。
- 不新增复杂的自动模型池或付费模型级联重试。
- 不提交、推送或发布版本。
