# 家园专用宠物与 2.5D 移动设计

## 目标

在家园场景中停止复用桌面 `PetWindow`，改为由家场景内部绘制和驱动一只独立宠物。第一阶段使用带方向标记的方块验证二维移动、2.5D 深度表现、右键目的地指令和低精力自动睡眠，为后续替换正式模型与动画资源建立稳定接口。

## 范围

第一阶段包括：

- 进入家园时隐藏桌面宠物，退出家园时恢复。
- 家园宠物使用独立二维世界坐标和行为控制器。
- 右键地面后直线移动到目标点。
- 目标始终限制在倾斜的可行走多边形内。
- 根据脚底纵坐标表现远小近大的 2.5D 深度。
- 提供左前、右前、左后、右后四方向动画接口。
- 精力不足时优先走到已放置地毯睡觉；地毯不可用时走到默认睡眠点。
- 用户移动指令可打断自动睡眠行为，并启动短暂重试冷却。
- 保存家园宠物最后的二维位置。

第一阶段不包括家具碰撞、绕行寻路、导航网格、八方向动画、正式宠物模型、多房间系统和复杂家具互动。

## 架构

### `home_pet.py`

新增与 PyQt 界面无关的家园宠物逻辑模块。核心 `HomePetController` 维护：

- 二维世界坐标和当前目标。
- `idle`、`manual_walk`、`auto_sleep_walk`、`sleeping` 四种行为状态。
- 左前、右前、左后、右后四方向朝向。
- 自动睡眠目标选择和用户打断后的冷却。
- 基于时间增量的直线移动更新。
- 可行走区域限制、到达判定和位置序列化。

控制器不加载图片、不持有 QWidget，也不直接保存文件。调用者向它提供精力、睡眠点和经过时间，并消费其位置与行为结果。

### `home_scene.py`

`HomeSceneWindow` 继续负责场景、家具、相机和装修交互，并新增以下职责：

- 创建和逐帧驱动 `HomePetController`。
- 将右键画布局部坐标转换为世界坐标并下达手动移动目标。
- 从共享成长状态读取精力和睡眠状态。
- 根据地毯放置状态计算自动睡眠目标。
- 绘制方块占位宠物、朝向标记、阴影和睡眠标记。
- 将地毯、宠物和高家具按明确层级渲染。
- 在合适时机持久化二维位置。

装修模式继续隐藏宠物并禁用移动指令，避免右键移动与家具编辑冲突。

### `pet.py`

`PetWindow` 不再承担家园内移动和渲染。它只负责家园生命周期切换：

- 进入家园时隐藏桌面宠物并启动家园实体。
- 离开家园时停止家园实体并恢复桌面宠物。
- 两种实体共享精力、饥饿、心情、`sleeping` 和 `sleep_mode`，但不共享坐标、速度、动画帧和临时目标。

## 坐标与可行走区域

家园继续使用 `1800×768` 世界和 `900×768` 视口。宠物位置以脚底中心点为锚点，所有移动、缩放、目标吸附和遮挡排序均以该点为准。

新增 `HOME_WALKABLE_POLYGON` 描述背景中的倾斜地面。用户点击地面外部时，将目标投影到多边形最近边界，而不是拒绝指令。渲染横坐标为 `world_x - camera_x`，纵坐标保持世界纵坐标，因此相机移动不会修改宠物真实位置。

深度值由脚底纵坐标在可行走区域中的归一化位置得到，并用于：

- 在受限范围内线性调整宠物绘制比例，形成远小近大效果。
- 轻微调整世界移动到屏幕像素的视觉速度，使近处移动自然。
- 与沙发、植物等高家具进行脚底纵坐标排序。

## 交互与状态流

### 右键移动

1. 仅在家园可见且未装修时处理右键。
2. 场景按钮和其他控件区域不触发移动。
3. 点击位置加上相机偏移后转换为世界坐标。
4. 目标限制到可行走多边形。
5. 根据目标向量选择四方向，并进入 `manual_walk`。
6. 每帧按真实经过时间推进；进入到达容差后停止并转为 `idle`。
7. 新的右键目标直接覆盖旧目标，不建立指令队列。

### 自动睡眠

1. 宠物处于 `idle`、精力低于现有阈值且不在冷却中时，触发自动睡眠。
2. 已放置且未收纳地毯时，使用地毯中心附近的可行走点。
3. 地毯未购买、已收纳或无有效位置时，使用固定默认睡眠点。
4. 宠物进入 `auto_sleep_walk`，到达后转为 `sleeping`。
5. 睡眠继续使用现有共享状态和精力恢复规则。
6. 精力达到现有自动唤醒阈值后转回 `idle`。

### 用户优先级

- 用户右键可覆盖 `auto_sleep_walk`。
- 宠物已经睡着时，右键先唤醒，再执行手动移动。
- 用户打断自动睡眠后设置约 60 秒的运行时冷却，避免低精力立即触发折返。
- 装修、退出家园或应用隐藏会取消临时目标，但保留最后有效位置。

## 动画与占位渲染接口

预留以下动画名称：

- `idle_front_left`
- `idle_front_right`
- `idle_back_left`
- `idle_back_right`
- `walk_front_left`
- `walk_front_right`
- `walk_back_left`
- `walk_back_right`
- `sleep`

第一阶段使用不同颜色或箭头标记方向的方块。方块脚底带椭圆阴影，行走时做轻微上下起伏，睡眠时降低高度并显示简单的 `Z` 标记。占位绘制集中在单独渲染函数中，未来替换精灵序列不改变控制器和输入逻辑。

## 渲染层级

渲染顺序为：

1. 背景和墙饰。
2. 地毯等地面家具。
3. 根据脚底纵坐标动态排序的宠物、沙发和植物。
4. 场景按钮、装修选中框和装修侧栏。

家具在第一阶段只参与绘制层级，不参与碰撞。

## 存档与兼容

在已有 `home_scene` 字典中新增：

```text
home_scene.pet_position = {x, y}
```

只持久化最后有效位置，不保存当前目标、路径、动画帧、行为状态或冷却剩余时间。保存时机包括到达目标、进入或离开睡眠、退出家园以及低频位置检查，避免逐帧写盘。

旧存档只有 `home_scene_dog_world_x` 时，将其作为新位置的初始 `x`，并使用默认入口点的 `y`。共享成长字段保持现有格式，不新增第二套精力或睡眠数据。

## 异常与边界处理

- 非数字、无穷大或缺失的位置恢复为安全默认点。
- 无效目标统一限制到可行走区域。
- 地毯位置无效、素材缺失或已收纳时使用默认睡眠点。
- 帧间隔过大时限制单次更新时间，避免窗口卡顿后瞬移越过目标。
- 场景销毁或退出时停止计时更新，不让隐藏实体继续改变状态。
- 装修状态下忽略家园宠物输入和自动行为。

## 测试设计

新增 `tests/test_home_pet.py`，先写失败测试，覆盖：

- 坐标与目标限制到可行走区域。
- 基于时间增量的直线移动和稳定到达。
- 四方向判断。
- 新目标覆盖旧目标。
- 地毯优先与默认睡眠点兜底。
- 自动睡眠、自动唤醒、用户打断和冷却。
- 位置序列化不包含临时行为。

扩展 `tests/test_home_scene.py`，覆盖：

- 进入和退出家园时桌面宠物可见性切换。
- 家园实体在场景内部绘制，不再移动桌面窗口。
- 右键坐标转换和按钮区域排除。
- 装修时隐藏实体并禁用移动。
- 地毯变换、收纳和放置会更新睡眠目标。
- 深度缩放范围和渲染层级。
- 旧一维位置迁移。

验证命令：

```text
python -m pytest -q tests/test_home_pet.py tests/test_home_scene.py tests/test_scene_system.py
python -m pytest -q
```

## 验收标准

- 进入家园后桌面宠物消失，场景内出现带方向标记的方块宠物。
- 右键目标会让方块在倾斜地面范围内直线移动。
- 方块在远处缩小、近处放大，并能正确出现在高家具前后。
- 精力不足时优先前往已放置地毯睡觉，没有可用地毯时前往默认点。
- 用户可随时右键打断自动行走或唤醒睡眠。
- 退出并重新进入家园后恢复最后二维位置，但不恢复未完成的移动目标。
- focused tests 与全量测试全部通过。
