# 小屋睡眠动画接入设计

日期：2026-08-11
状态：用户已确认

## 目标

把用户生成的 8 帧睡眠帧表接入小屋宠物的正式 `sleeping` 状态，并采用比行走更慢的独立播放速度。走向地毯、自动睡眠、手动睡眠、唤醒和固定显示大小等现有状态逻辑保持不变。

## 输入素材

源文件：

`C:\Users\sheen\Downloads\job_e8a775fa6286425e9f59859b00a3b652-transparent.png`

项目目标：

`assets/scenes/home/home-pet-sleep.png`

素材规格：

- 整图 `1920×1920`。
- 3×3 网格，每格 `640×640`。
- 前 8 格为有效睡眠帧，第 9 格为空，不参与播放。
- PNG 具有 alpha 通道；项目复制必须保留原始像素，不覆盖先前的静态参考图 `home-pet-sleep-reference.png`。

## 帧几何

逐帧 alpha 主体范围约为：

- 最左 `x=28`，最右 `x=612`。
- 最上 `y=179`，最下 `y=457`。

为避免每帧独立裁剪引起位置和尺寸抖动，所有帧统一使用帧内裁剪框：

`QRect(24, 176, 592, 288)`

第 `i` 帧的源矩形通过该固定矩形平移 `(i % 3) * 640, (i // 3) * 640` 获得。帧索引始终对 `8` 取模，因此永远不会访问第 9 格。

## 播放速度

- 新增独立常量 `HOME_PET_SLEEP_FPS = 3.0`。
- 8 帧完整循环时长约 `2.67 秒`。
- `home_pet_sleep_frame(now)` 只在 `HomePetController.state == "sleeping"` 时根据时间推进；其他状态返回第 0 帧。
- 行走继续使用 `HOME_PET_WALK_FPS = 8.0`，两个速度互不影响。

## 状态与渲染

- `manual_sleep_walk` 与 `auto_sleep_walk` 继续播放现有四方向行走帧。
- 抵达睡眠点进入 `sleeping` 后，`home_pet_render_spec(now)` 选择睡眠帧表。
- 睡眠帧不镜像，保持素材朝向。
- 睡眠渲染高度为站立基础高度的 `62%`，即 render spec 使用 `visual_scale=0.62`；宽度始终按统一源矩形比例计算，不拉伸。
- 脚底/接触锚点使用睡眠轮廓的下沿：`contact_center_x=0.50`、`contact_width=0.84`、`contact_foot_y=0.98`。
- 小狗世界脚底位置、相机跟随、家具深度排序和点击锚点继续使用现有 render rect，不引入远近缩放。

## 阴影与回退

- 睡眠帧表已经包含柔和接触阴影。正式睡眠 pixmap 有效时，`_draw_home_pet()` 跳过额外的程序椭圆阴影，避免双重阴影。
- 睡眠素材缺失或加载失败时，`home_pet_render_spec()` 返回 `None`，继续使用现有睡眠方块和 `Z Z` 占位表现；此时仍绘制现有程序阴影。
- 素材缺失不影响状态机、睡眠记录、能量恢复和唤醒。

## 测试

修改生产代码前先添加失败测试，覆盖：

1. 新素材存在、为 `1920×1920` 且具有 alpha 通道。
2. 睡眠源矩形仅访问前 8 格，并在第 8 个索引后回到第 0 帧。
3. `3 FPS` 节奏：`now=0` 为第 0 帧，`now=1/3` 为第 1 帧，`now=8/3` 回到第 0 帧。
4. `sleeping` 选择睡眠 pixmap、固定裁剪、`visual_scale=0.62`，非睡眠状态不使用该 pixmap。
5. 睡眠素材缺失时回退到现有占位渲染。
6. 正式睡眠素材渲染时不叠加程序阴影，回退占位时仍保留阴影。
7. focused tests、完整 `pytest -q`、`py_compile` 与 `git diff --check`。

## 手工验收

1. 从快捷菜单选择睡觉，确认小狗先走到地毯，再切换为睡眠动画。
2. 观察一轮约 `2.67 秒`，确认呼吸节奏舒缓且没有跨帧抖动。
3. 确认睡眠小狗大小固定、贴合地毯，没有双重阴影。
4. 再次选择睡觉唤醒，确认恢复正坐待机并保留当前位置。
