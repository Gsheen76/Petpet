# 右键快速双击闪退修复设计

## 背景与故障证据

用户在桌面小狗菜单关闭时快速双击鼠标右键，`pythonw.exe` 会直接退出。Windows 应用日志记录到 2026-08-21 14:31:40 的 `APPCRASH`：故障模块为 `Qt5Core_conda.dll`，异常代码为 `0xc0000005`。这说明故障发生在 Qt 原生对象生命周期中，而不是可捕获的普通 Python 异常。

当前右键操作同时经过 `PetWindow.mouseReleaseEvent()` 与 `PetWindow.contextMenuEvent()`。菜单显示后，`BubbleMenu` 又通过应用级事件过滤器把菜单外的鼠标按下转换成一个 `QTimer.singleShot(0, self._close)` 延迟关闭。快速第二次右键发生在小狗本体上时，这三个行为可能交错：旧菜单排队关闭、宠物再次请求菜单、旧 Qt 窗口被关闭并由 `WA_DeleteOnClose` 删除。现有 0.25 秒节流只能减少重复创建，不能阻止已经排队的关闭回调与菜单复用相撞。

## 目标

- 菜单关闭时快速连续右键小狗不会导致进程闪退。
- 已显示的菜单收到小狗本体右键时保持同一个实例，不关闭后重建。
- 保留现有菜单外点击关闭、页面切换、预热和首次打开速度。
- 不改变菜单外观、按钮布局、左键拖动或其他互动行为。

## 方案比较

### 方案 A：小狗右键视为菜单内部请求，并复用可见菜单（采用）

应用级事件过滤器识别“右键按下发生在所属小狗本体上”，不为这次事件排队关闭菜单。`open_bubble_menu()` 只要发现现有菜单仍可见，就执行跟随定位、置顶和激活，然后返回同一实例；不再仅依赖 0.25 秒窗口。

这个方案直接移除竞态触发条件，改动局部，并保留所有预热和关闭行为。

### 方案 B：取消菜单预热

可以减少预先创建的 Qt 对象，但快速第二次右键仍可能让活动菜单进入延迟关闭与重新创建竞态，并会恢复首次打开卡顿，因此不采用。

### 方案 C：移除 `WA_DeleteOnClose` 并重构菜单所有权

可以从底层改变生命周期，但会扩大到所有菜单页面、属性气泡和退出清理，回归风险明显高于本次问题，不采用。

## 详细设计

### 1. 识别小狗本体右键

`BubbleMenu.eventFilter(watched, event)` 在现有“菜单外点击”判断之前增加一个窄条件：

- 事件类型必须是 `QEvent.MouseButtonPress`；
- 按键必须是 `Qt.RightButton`；
- `watched` 必须是该菜单所属的 `pet`。

满足时直接返回 `False`，让事件继续交给小狗处理，但不安排 `_close()`。左键点击小狗和点击其他窗口仍保持原来的菜单外关闭行为。

### 2. 可见菜单幂等复用

`PetWindow.open_bubble_menu()` 读取当前 `_bubble_menu` 后，只要该对象可见且没有进入 `_closing`，就：

1. 调用 `follow_pet()` 校正位置；
2. 调用 `raise_()` 和 `activateWindow()` 保持菜单在前；
3. 返回现有菜单。

如果对象已经不可见、正在关闭或包装的 Qt 对象已删除，则继续执行现有关闭清理和创建流程。保留 `_last_bubble_menu_t` 兼容现有状态，但不再让安全性依赖时间窗口。

### 3. 生命周期边界

- 菜单真正的外部点击仍通过零延迟回调关闭，避免在 Qt 事件过滤器栈内直接销毁窗口。
- 页面切换仍主动关闭旧菜单并创建目标页面。
- 不复用正在 `_closing` 的菜单。
- `RuntimeError` 仍视为 Qt 包装对象已经失效，随后创建新菜单。

## 测试策略

1. 单元回归：活动菜单的事件过滤器收到“小狗本体右键按下”时，不调用或安排 `_close()`。
2. 行为回归：可见且未关闭的菜单被重复请求时返回同一实例，不调用旧菜单 `_close()`，并重新定位和置顶。
3. 保留验证：左键点击小狗或点击其他窗口仍会安排菜单关闭。
4. 真实 Qt 压力验证：在独立 Python 子进程中连续发送右键按下、释放和上下文菜单事件，进程正常退出且无 `Qt5Core` 崩溃。
5. 运行完整 `python -m pytest -q`，确保菜单、桌宠和其他功能无回归。
