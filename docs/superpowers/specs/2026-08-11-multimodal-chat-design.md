# 图文陪伴聊天设计

## 目标

将 Petpet 的在线聊天模型替换为 `GLM-4.7-Flash` 与 `GLM-4.6V-Flash`，并允许用户仅在视觉模型下上传一张本地图片，让小狗结合图片和文字聊天。

## 模型与兼容性

- 默认模型：`glm-4.7-flash`，显示名 `GLM-4.7-Flash`，仅发送文本。
- 视觉模型：`glm-4.6v-flash`，显示名 `GLM-4.6V-Flash`，支持文本加一张图片。
- 老配置的 `glm-4-flash` 不再显示；读取时安全归一化为新的默认模型，已有 API Key 保持不变。
- 两个模型继续调用既有智谱 `POST /api/paas/v4/chat/completions` 流式接口。
- 陪伴聊天显式传入 `thinking: {"type": "disabled"}`：`GLM-4.7` 默认开启思考，而 Petpet 的短回复上限为 200 tokens，关闭思考可避免推理内容耗尽正文预算。

官方接口对 `glm-4.6v-flash` 的图片消息使用同一条用户消息中的 `image_url` 与 `text` 内容块；本地图片可用 Base64 传递。[GLM-4.6V-Flash 文档](https://docs.bigmodel.cn/cn/guide/models/free/glm-4.6v-flash)

## 界面

- 聊天工具栏新增“上传图片”按钮，但仅在选中 `GLM-4.6V-Flash` 时可见。
- 选择图片后，在输入区上方显示文件名、缩略图和移除按钮；每次仅允许一张待发送图片。
- 切回 `GLM-4.7-Flash` 时清除尚未发送的待选图片并隐藏上传入口，避免把图片误发给纯文本模型。
- 图片可不带文字单独发送；界面给模型的文字回退为“请看看这张图片，和我聊聊吧”。
- 发送后的用户气泡带有缩略图；重启后仍可显示。

## 本地数据与隐私

- 原图只在当前发送请求时读取、编码并交给 `GLM-4.6V-Flash`，不复制到应用数据目录。
- 发送成功或失败前，为聊天历史生成长边不超过 320 px 的 JPEG/PNG 缩略图，保存到用户数据目录的 `chat_images/`。
- `memory.json` 只保存用户文字、缩略图相对路径、原文件名及时间，不保存 Base64，也不保存原图路径。
- 清除聊天记忆时同时删除受本应用管理的历史缩略图目录；删除失败不阻止记忆清除。
- 支持 PNG、JPG/JPEG、WEBP，单张原图上限 10 MiB；读取失败、图片损坏或超限时不启动请求，并在聊天窗口明确说明。

## 请求与记忆

- 无图：沿用当前字符串 `content` 消息格式。
- 有图：最后一条用户消息替换为 `[{"type":"image_url","image_url":{"url":"<base64>"}}, {"type":"text","text":"<文字>"}]`；`<base64>` 是原始 Base64 字符串，不是 Data URL。
- 发送后只将可读文本（例如 `我发送了一张图片：cat.png`）写入模型的后续文本历史；不会在后续请求重复上传图片。
- 模型失败仍走既有离线回复；UI 仍保存用户缩略图和离线回复，保证历史连续。
- 流式响应若只返回结束标记、没有任何正文，视为 `empty_response` 失败并走离线回复；绝不把空字符串写入聊天历史。
- `rate_limit` 与 `empty_response` 只显示成自然的小狗提示，不向用户暴露内部错误码。

## 验收

- 下拉菜单只显示两种新模型，旧值自动迁移。
- 视觉模型的请求 JSON 含一张 Base64 `image_url` 和一块文本；纯文本模型不含图片块。
- 上传控件的显示条件、预览、移除、发送后历史缩略图、重启加载、清除记忆和错误校验都有自动化测试。
- 运行 focused tests、`pytest -q`、`py_compile` 和 `git diff --check`。
