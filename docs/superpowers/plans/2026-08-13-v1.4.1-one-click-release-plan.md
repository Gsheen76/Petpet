# Petpet v1.4.1 One-Click Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the current confirmed Petpet feature set as v1.4.1 and add a reusable PowerShell command that safely orchestrates future Windows and macOS GitHub releases.

**Architecture:** `scripts/release.ps1` remains the single operator entry point and composes existing local Windows packaging with the existing macOS GitHub Actions matrix. GitHub Release stays draft until the script verifies the tag, public source commit, workflow result, and all four platform assets. Metadata and workflow contracts are protected by Python tests; release-side failures stop without force pushes or destructive Git operations.

**Tech Stack:** Python 3.11, pytest, PowerShell 5.1+, Git, GitHub CLI, PyInstaller, GitHub Actions, Obsidian Markdown.

- [ ] **Step 3: Implement the preflight and local verification stages**

Create an advanced PowerShell script with:

```powershell
param(
    [Parameter(Mandatory = $true)]
    [ValidatePattern('^\d+\.\d+\.\d+$')]
    [string]$Version
)
$ErrorActionPreference = 'Stop'
```

Resolve the repository root from `$PSScriptRoot`; validate `version.py`, release notes, named branch, clean tree, tools, authentication, and `origin/main` ancestry. Invoke tests, compilation, diff check, Windows build, exact-path EXE smoke test, ZIP creation, and SHA-256 manifest generation. Every native command must be followed by an exit-code check that throws on failure.

- [ ] **Step 4: Implement Git, draft Release, macOS, and final gates**

Only then run:

```powershell
gh release edit $tag --draft=false --prerelease=false --latest
```

If the Release is already public and complete, perform verification and return success. Any mismatch throws before publication and prints the exact rerun command.
