# Petpet v1.4.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将当前家园功能作为 `v1.4.0`，以 README、发布说明和 Windows/macOS 四项完整资产一次性公开到 GitHub Releases。

**Architecture:** `version.py` 继续作为唯一版本来源，`tests/test_release_metadata.py` 锁定版本、README 和发布说明的一致性。Windows 使用当前 worktree 本地 PyInstaller 构建；macOS 使用同一标签触发 GitHub Actions 双架构矩阵。Release 先保持 draft，四项资产验证后再公开。

**Tech Stack:** Python 3.11/3.12、PyQt5、pytest、PyInstaller、PowerShell、Git、GitHub REST API、GitHub Actions、SHA-256。

## Global Constraints

- 工作区固定为 `D:\Agent_project\Petpet\.worktrees\home-scene-system`，分支为 `codex/home-scene-system`。
- 发布版本固定为 `1.4.0`，Git 标签固定为 `v1.4.0`，Release 标题固定为 `Petpet v1.4.0`。
- 不执行 `git reset` 或 `git checkout`，不回退当前功能改动，不使用强制推送。
- README 必须反映实际五入口快捷菜单与“小屋”直接入口。
- 四个正式资产全部成功后才把 Release 从 draft 改为公开。
- 不在命令输出、文档或 Git 中记录 GitHub token、API Key、个人对话或用户存档。
- 项目 Markdown 同步到 `D:\Github Desktop\My-Obsidian\项目\Petpet\发布系统`，发布后更新 `Petpet 总档案.md`。

Run: `powershell -ExecutionPolicy Bypass -File scripts\build_windows.ps1`
Expected: `dist/Petpet.exe` 存在且构建命令退出码为 0。

- [ ] **Step 2: 创建便携 ZIP**

在 `dist/release-v1.4.0/windows/` 放入 `Petpet.exe` 与 `README.md`，使用 `Compress-Archive` 生成 `dist/Petpet-v1.4.0-windows.zip`。复制前解析所有绝对路径并确认目标均位于当前 worktree 的 `dist` 下。

- [ ] **Step 3: 隐藏启动冒烟并计算哈希**

```powershell

  dist\Petpet.exe,dist\Petpet-v1.4.0-windows.zip
```

Expected: EXE 可启动；两个资产均非零且 SHA-256 已记录。

### Task 4: 推送 main、标签并构建 macOS

**Files:**
- Remote ref: `origin/main`
- Remote tag: `v1.4.0`
- Workflow: `.github/workflows/build-macos.yml`

**Interfaces:**
- Consumes: Task 2 发布提交与 Task 3 Windows 资产。
- Produces: 远端 `main`、`v1.4.0` 标签和两个成功的 macOS artifact。

- [ ] **Step 1: 核对远端仍可快进**

Run:

```powershell
git fetch origin main --tags
git rev-list --left-right --count HEAD...origin/main
git merge-base --is-ancestor origin/main HEAD
```

Expected: `origin/main` 是 `HEAD` 祖先；否则停止，不推送。

- [ ] **Step 2: 推送发布提交与注释标签**

Run:

```powershell
git push origin HEAD:main
git tag -a v1.4.0 -m "Petpet v1.4.0"
git push origin v1.4.0
```

Expected: 两次推送成功，禁止 `--force`。

- [ ] **Step 3: 触发 macOS 双架构工作流**

从 `git credential fill` 读取 GitHub 凭据到内存变量，不输出 token。调用：

```text
POST /repos/Gsheen76/Petpet/actions/workflows/build-macos.yml/dispatches
{"ref":"v1.4.0"}
```

轮询本次 `workflow_dispatch` run，直到 `status=completed`；要求 `conclusion=success`。连续失败或任一架构失败则停止发布。

- [ ] **Step 4: 下载并展开两个 artifact**

通过 Actions artifacts API 下载 `Petpet-macOS-arm64` 与 `Petpet-macOS-intel`，将外层 artifact ZIP 解压到 `dist/macos-artifacts/v1.4.0/`，得到：

- `Petpet-v1.4.0-macOS-arm64.zip`
- `Petpet-v1.4.0-macOS-intel.zip`

验证两个 ZIP 非零并计算 SHA-256。
