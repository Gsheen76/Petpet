# Petpet v1.6.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将当前 `main` 的全部已验证功能以 `v1.6.0` 发布到 GitHub，并提供 Windows 与 macOS 双架构完整资产。

**Architecture:** 在从 `main` 创建的隔离工作树中准备并提交发布元数据，然后复用 `scripts/release.ps1` 完成测试、构建、原子推送、macOS Actions、资产校验和公开 Release。发布成功后将发布提交快进到本地 `main`，同步 Obsidian 事实记录并清理隔离工作树。

**Tech Stack:** Python 3, pytest, PyInstaller, PowerShell, Git, GitHub CLI, GitHub Actions, Obsidian Markdown.

## Global Constraints

- 版本固定为 `1.6.0`，标签固定为 `v1.6.0`，Release 标题固定为 `Pet陪它 v1.6.0`。
- 远端 `main`、带注释标签 `v1.6.0` 和 Release target 必须指向同一提交。
- 必需资产为 `Petpet.exe`、`Petpet-v1.6.0-windows.zip`、`Petpet-v1.6.0-macOS-arm64.zip`、`Petpet-v1.6.0-macOS-intel.zip`，均为 `uploaded` 且大小大于零。
- 同时上传 `Petpet-v1.6.0-SHA256SUMS.txt`；macOS 保留未签名、未公证说明。
- 不得强制推送、覆盖不同内容的资产、移动已有冲突标签或公开缺少资产的 Release。
- 保留主工作区既有 `.superpowers` 未跟踪文件，不把便携 GitHub CLI 或构建产物提交进仓库。

### Task 2: 运行一键发布并等待四平台资产

**Files:**
- Execute: `scripts/release.ps1`
- Generate ignored: `.tools/gh/**`
- Generate ignored: `build/**`, `dist/**`

**Interfaces:**
- Consumes: Task 1 的干净发布提交和 `docs/RELEASE_NOTES_v1.6.0.md`。
- Produces: 远端 `main`、注释标签 `v1.6.0`、公开 GitHub Release 和五项上传资产。

- [ ] **Step 1: 预检远端冲突**

通过 GitHub API 和 `git ls-remote` 确认远端不存在指向其他提交的 `v1.6.0` 标签或 Release。若不存在则继续；若存在且完整并指向当前发布提交，则进入幂等验证；其他情况停止。

- [ ] **Step 2: 准备便携 GitHub CLI（仅在缺失时）**

若 `Get-Command gh` 不存在，从 GitHub CLI 官方最新 Windows amd64 ZIP 下载到临时目录，校验 ZIP 可解压且 `gh.exe --version` 成功，再放入已忽略的 `.tools/gh/`。不得修改系统 PATH 或提交二进制。

- [ ] **Step 3: 执行发布脚本**

Run:

```powershell
.\scripts\release.ps1 -Version 1.6.0
```

脚本必须依次完成全量测试、全部受跟踪 Python 文件编译、diff 检查、Windows PyInstaller 构建、隐藏启动 4 秒冒烟、Windows ZIP 与 SHA256、GitHub 登录、注释标签、原子推送、草稿 Release、macOS Actions 和最终公开验证。

- [ ] **Step 4: 若网络或 Actions 暂时失败，安全重入**

不得手工覆盖资产。确认远端草稿、标签和已上传资产与本地内容一致后，重复运行同一命令；脚本会跳过哈希一致的既有资产和已上传的 macOS ZIP。

### Task 3: 独立验证公开 Release 并同步记录

**Files:**
- Create: `D:/Github Desktop/My-Obsidian/项目/Petpet/发布系统/Petpet v1.6.0 发布说明.md`
- Create: `D:/Github Desktop/My-Obsidian/项目/Petpet/发布系统/Petpet v1.6.0 发布实施记录.md`
- Modify when present: `D:/Github Desktop/My-Obsidian/项目/Petpet/Petpet 总档案.md`

**Interfaces:**
- Consumes: GitHub 公开 Release、发布提交和本地 Windows SHA256。
- Produces: 可复核的远端发布事实、Obsidian 发布说明和实施证据。

- [ ] **Step 1: 验证远端引用与 Release 元数据**

检查 `origin/main`、`refs/tags/v1.6.0^{}` 和发布提交 SHA 完全相等；Release 必须 `draft=false`、`prerelease=false`、`tagName=v1.6.0`。

- [ ] **Step 2: 验证资产**

逐项检查四项必需资产和校验和文件的名称、状态、大小和正式下载 URL。下载资产到 `dist/release-v1.6.0/final-*` 临时目录，计算 SHA256；Windows EXE/ZIP 必须与本地构建一致。

- [ ] **Step 3: 同步 Obsidian**

使用 YAML frontmatter、wikilinks和 callout 记录版本亮点、提交 SHA、标签、Release URL、五项资产、测试结果、Actions run、哈希和未签名 macOS 说明。若本机 Obsidian CLI 版本仍不可用，如实记录本地文件校验，不伪造 CLI 成功。

- [ ] **Step 4: 快进本地 main 并清理**

从主仓库将本地 `main` 快进到发布提交，在主线再次运行 `python -m pytest -q`。绿色后移除 `.worktrees/release-v1.6.0` 并删除已合并分支；保留其他工作树。

- [ ] **Step 5: 最终汇报**

报告公开 Release URL、提交与标签 SHA、各资产大小与 SHA256、主线测试数量、Obsidian 路径及任何外部限制。
